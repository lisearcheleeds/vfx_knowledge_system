# DungeonInn：この版で採用するVFX制作方針

[受領一覧](INPUT.md)に対する、VFXアーティストとしての制作主案。以下には初期案も含む。剣・短剣・大剣の最新採用は末尾の2026-10-06改訂を優先する。その他を一括承認した記録ではない。火球の最新採用は[Core単独への変換記録](runs/fireball-downscale-2026-10-04.md)、品質基準版の履歴は[初回制作記録](runs/fireball-2026-10-04.md)へ記載する。現段階で良い初稿を作るために、形・素材・時間・階層を具体的に決める。個々の構成は[演出カタログ](CATALOG.md)から参照する。

## 形で攻撃を読み分ける

| 分類 | 主役として採用する形 |
| --- | --- |
| 剣 | 判定後の完成した三日月残像。内側の抜きと戻り短縮で消える。判定契約90度は別に保持 |
| 斧 | 終端が厚い120度の弧と遅れる刃重 |
| 大剣 | 剣ベースの幅広い三日月、少し長い残留。判定契約110度は別に保持 |
| 鎌・旋風斬 | 一周する連続した弧。鎌は細く、旋風は発動の解放を強く |
| 短剣 | 深い内側抜き、細い帯、全体幅1:奥行5の三日月 |
| 槍（初期案） | 攻撃軸の針と一点の圧縮 |
| 棒・拳・盾 | 接触の面、幅広い星、遅れる薄い圧力環 |
| 爪・牙 | 平行する短い切り線／内へ閉じる二点 |
| 矢・ボルト | ゲーム入力に従う実体と一本の短い尾 |
| 杖・ワンド | 丸い柔らかな核／小さく鋭い滴状核 |
| 火球 | 飛翔は面上密度と折り曲げ式ビルボードのCore単独。射出・着弾は体積の熱解放・膨張・冷却を保持 |
| 火炎の息 | 実範囲に合う円錐殻と大きな炎舌の一回の解放 |

動作中に刃を見せる場合はメッシュ展開を比較する。判定後の三件は完成外形を置く残像方式。武器先端の実軌道に沿う部分だけ履歴帯を添える。粒子は火花・葉・破片・炎舌等の役割へ限定し、形状の曖昧な粒子雲で全ての攻撃を代用しない。

## この版の配色

以下はsRGBの色指定。Materialの線形色・HDR発光値への変換はAdapterで行う。

| 用途 | 主色 | 面と芯 |
| --- | --- | --- |
| 金属武器（ユーザー改訂） | 淡黄 `#FFEAA5` → 橙 `#FF9B45` | 色の濃い面と明るい外縁、端はグラデーションで透明へ |
| 無属性魔法 | 淡青 `#86CCF0` | 青の面と小さな青白の芯 |
| 火炎 | 橙 `#F68732`、赤 `#B7482B` | 小さな淡黄の熱核と橙の大きな舌 |
| HP回復 | ミント `#67DDA0` | 柔らかな葉・滴と短い白芯 |
| MP回復 | 淡青 `#53BDF5` | 細い結晶と静かな周回 |
| 攻撃強化 | 暖金 `#F3BD63` | 上向きの形と小さな付与ピーク |
| 攻撃低下 | 紫 `#9361BC`、暗紫 `#4B345D` | 欠けた下降形と低明度の面 |
| 土の衝撃 | 土色 `#9B8164` | 白い接触芯と薄い粉塵 |

色に加え、HPは葉、MPは結晶、強化は上向き、弱体は欠けた下向きで読む。敵味方の識別色は未提供であり、この属性配色から陣営を推測しない。識別を追加する場合はゲーム側の意味とProfileへ対応付ける。

## 明度と時間の仕上げ

主役の色面、細い発光芯、暗い外縁を別に持つ。最初のピークは小さく高く、減衰は大きな侵食と色の変化で作る。全面の白い面にBloomだけを乗せる仕上げは採用しない。

予兆は中心へ集める、発動は外へ解放する、余韻は薄く裂いて消す。この運動方向を一貫させ、接触と無関係なタイミングに最も明るいピークを置かない。

Recipeの0.04秒ピーク、0.20秒減衰、粒子個数などは、初稿を制作するために選んだ値。受領したマスタの詠唱・予備動作・速度・状態期間とは別の値であり、実測値ではない。

## 寸法と範囲

Wは対象Actorの身体幅、Hは身長、Lは武器の可視長、Rはゲームが渡す実範囲。物理寸法はメートルを基準とし、Actor/武器の寸法は実アセットのBoundsから得る。比率の基準を接続時に一つへ統一する。

主役の範囲境界は実際のR・角度で作る。装飾の拡大環と固定の境界を別にし、見た目のScaleでゲームの範囲を変更しない。斬撃の運動面は実モーション、地面境界は実判定の面へ置く。

火球の着弾Rangeは範囲表示側の責務としてPrefabから削除した。実範囲2mの契約は保持し、装飾BlastWaveを範囲判定にしない。

## 準備・発動・飛翔・命中・状態の所有

- 準備は使用者、飛翔は実投射体、接触は実命中点、状態は実対象に置く。
- cast-start/cast-progress、attack-active、launch、impact/hit-confirmed、effect-applied/refresh/removeは必要な意味上の入力。この名前のイベントが既存コードにあるとは断定しない。
- 詠唱進捗と実発動に同期し、中断から成功演出を出さない。
- 状態applyは状態ハンドラが一回だけ所有する。Skill104とActorEffect8等の参照は知識の共用であり、二つのEmitterを同時発生させる指示ではない。
- 号令・鼓舞は自分への強化。隣のActorへ広がるバフ波を出さない。
- 火炎の息は一回の瞬間範囲。継続ブレスや刻みダメージを新設しない。

## 長時間状態の品質

300秒の活力は、良い付与の一回と小さな識別記号に分ける。大きな常時地面環・煙・火花を5分間維持しない。10秒の回復も毎秒フル演出を再生せず、実回復刻みでは記号と小光点だけを脈動させる。

Actor一体につきHP・MP・攻撃強化・攻撃低下をそれぞれ一組にまとめる。元の状態を複数保持し、代表する形だけ集約する。ゲームのスタック・回復量・期限は変更しない。解除・再付与・複合状態の各機能の終端は実データへ追従する。

## 修正できる構成として保存する

共通Recipeの主案は `composes: required` で記録し、このプロジェクトは[BINDINGS.json](BINDINGS.json)で採用先と個別調整を指定する。ゲーム固有ID・範囲・速度・期間を共通Recipeへ固定しない。これは「ファイアボールは世界中で必ずメッシュ」という一般則ではなく、今回の具体的な制作案を選んだ結果である。比較用のcandidateは採用へ自動混入させない。

改訂時は主役の形・時間・素材・関係を変更し、revisionと索引を更新する。技法と素材を共有する。火球は射出・飛翔・着弾の専用Prefabを作成済みで、他の実行時EffectId、共用単位、Variantの境界は未確定。

## 火球の品質基準版からの改訂

ユーザー判断で、まず表示サイズ・負荷予算への削減を保留して品質を追求した。球Meshから内部密度へ変え、外炎・Trail・煙を重ねた品質基準版の制作値と93/100の主観評価は[初回制作記録](runs/fireball-2026-10-04.md)へ残す。他Recipeに制約の保留を自動適用しない。

後続では外炎の輪郭マスクを改訂し、合成への貢献を比較して外炎・Trail・煙・見えない火の粉を削除した。飛翔は面上密度と8頂点の折り曲げ式ビルボードのCore単独へ置換し、折り目を明部の外へ移して見た目承認を得た。最新の採用値は[変換記録](runs/fireball-downscale-2026-10-04.md)、採用構成は[Core単独Selection](runs/fireball-downscale-2026-10-04.selection.yaml)を正本にする。射出・着弾の体積構成は保持し、着弾Rangeは別責務へ分離した。

飛翔の外炎修正と構成削減は終了した制作作業。ゲーム時計・イベント・終了・Pool・階層復元、内部構造の独立レビュー、対象実機の密集負荷は今後の検証であり、見た目承認で完了扱いにしない。

## 参照した判断基準

行動・状態の伝達と、全体の一貫性・発生源の個性の両立は[Riot GamesのVFX教育資料](https://www.riotgames.com/en/artedu/visual-effects)を参照した。粒子の発生・運動と描画の分離は[Epic GamesのNiagara説明](https://dev.epicgames.com/documentation/en-us/unreal-engine/niagara-overview?application_version=4.27)を参照した。

上の具体的な構成・数値・配色は、このナレッジでの制作判断である。資料がDungeonInnの効果を再現・検証したことを示さない。

## 剣・短剣・大剣の採用改訂（2026-10-06）

最新値と承認範囲は[三種の制作記録](runs/slash-afterimage-2026-10-06.md)を正本とする。最初から完成した残像を配置し、内部UV流れと内側SDF抜きを分離する。0秒は透明、フェードインの目安はエフェクト全般0.05〜0.1秒、三件の保存値0.075秒。フェードイン開始から消失も並列に進める。初稿の短いピークや保持時間をこの残像へ自動適用しない。

短剣に別の切り/戻りの残像を作ることは要求されていない。大剣は剣の幅と残留を強める。部分指摘で既存の色・濃さ・立上り・流れ・方向・終端を捨てない。未使用武器・旧技法・共有素材は保持。保留対象の制作・改変は別の指示で行う。
