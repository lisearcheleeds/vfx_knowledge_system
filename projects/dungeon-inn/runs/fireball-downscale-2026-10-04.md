# ファイアボール：最高品質基準版からCore単独への変換例

## 参照範囲と承認

最高品質の基準版はDesktopDungeon `7c8f5e3e6967f0ec46b20017eff364f35cc6d1b3`。[初回制作記録](fireball-2026-10-04.md)に画像・動画・値を保存した。その後の実装は`6963c273`、承認と画像削除はローカル`d6781bb3`。Unity 6000.3.14f1 / URP 17.3.0 / Windows Editor / DX12。ユーザーが実物Previewを評価した。

ユーザーは基準版を93/100と評価し、削減後の飛翔は「完成品質に達したと言っていいでしょう」と承認した。最終版に新しい数値評価は付けない。承認は飛翔の見た目についてで、ゲームへの登録・実行・実機性能の合格ではない。

## 最高打点を作ってから削る

最初はコストと小さい表示の制約を保留し、目標とする炎の輪郭・熱・方向流れを作った。基準版はCube内の密度を64区間積分し、外炎4枚・native Trail・体積煙・火の粉を重ねた。これは品質の見本を得る段階で、性能無限で安全という意味ではない。

次に主役と補助を比較した。Coreだけで火球が成立していることを人間が確認し、補助層を削除した。体積の主役は面上密度近似へ置き換え、8頂点の折り曲げビルボードで描いた。最高品質の基準を参照して近似と削除を選ぶため、最初から最低限の見た目へ仕様を縮めなかった。

| 要素 | 基準版 | ゲーム用候補への判断 |
| --- | --- | --- |
| Core | 密度の房・吸収・発光を体積積分 | UV上の房・侵食・温度色へ近似。Shaderのfragmentは2回のNoise参照、体積積分なし |
| 固定描画 | Coreと外炎に各1個BurstのParticleSystem | MeshRendererと外部時計に変更。capを下げるだけでは実発生数が変わらない |
| FlameShell0〜3 | 方向流れの外炎4枚 | 矩形・三角形の辺が目立ち、主役への貢献も小さいため削除 |
| FlameTail | 履歴の黄橙→赤→煙色 | 削除。Core自身の赤い尾の房は保持 |
| SmokeWake | 体積煙、60個/s・寿命0.8秒・cap64 | 見た目に違和感があるため削除。煙を8個にする案は試していない |
| Embers | 6個/s・寿命0.18秒 | 主役に埋もれて見えないため削除。長命化案は実装していない |
| ルートParticleSystem | 子粒子のPreview用の再生制御 | 全粒子削除後は不要。PreviewをMeshだけにも対応させて削除 |

最終飛翔はルートTransform＋Core、MeshRenderer1つ、ParticleSystem0個。8頂点・6三角形。射出・着弾の体積構成はこの削減の対象外。着弾Rangeはユーザーが範囲表示の責務と判断して別途削除し、装飾BlastWaveは保持した。共通素材・Shaderは他用途に備えて保持した。

## 外炎の失敗と削除判断

開始フェード9%→25%、ノイズ±5%、四辺8%へ広げても、進行側を底辺とする三角形の角はあまり変わらないと指摘された。透明度だけの変更では輪郭が残っていた。

根元を半楕円キャップへ変え、ノイズが削った角を再表示しない別マスクを掛けた。改善は認められたが「Coreだけで良さそう」と裁定された。修正に投資した層でも、最終合成への貢献が小さければ削除する。

## 明部の比率と折り目

初期Meshは長さ方向の頂点y=1.5/0.5/-0.5/-1.5、UV.y=0, 1/3, 2/3, 1。主役のhead中心はUV.y=0.38、ノイズなしの半値範囲0.213〜0.547。折り目1/3ではheadがピークの約94.7%で、明るい楕円のほぼ中心を分断していた。

横からは見えても、前後から中央面が縮むと楕円の途中が途切れたように見えた。中央面の軸固定による短縮と、描画内容の比率不一致が重なると推定した。

8頂点のまま折り目をUV0.62/0.78へ移し、頂点yを1.5/-0.36/-0.84/-1.5とした。`y=1.5-3*UV.y`を維持して元の明部の長さとUVを保つ。前面/中央/後面は1.86/0.48/0.66m、Core localScaleは(1.5,1,1)、local位置(0,0.04,-0.27)、+Yを+Zへ回す。明部Shaderの式を変更せず、明部を前面へ収めた。

UV2.xに支点y、UV2.yに外端なら1/折り目なら0を格納。Shaderに折り目を重複定義しない。Boundsは(4.2,3.1,4.2)で回転範囲を含む。中央面が軸方向で縮む制約は残るが、そこを赤い尾側へ移した。

## UV時計と検証

WorldEffectMeshViewは外部から経過秒・Seed・Tintを受け、MaterialPropertyBlockを更新する。自身のUpdate時計なし。Shaderは_Timeを使わず、CPUでUVを書き換えない。Scene配置だけでは時間入力がなく、専用Effect Prefab Previewが時計を進める。ゲーム時計への接続は未実装。

compile Error0/既存Warning2、ShaderHasError=false、CodingRules/UsingDirectives違反0。保存PrefabのRenderer1/ParticleSystem0/子Core1、Mesh8頂点と折り目をnative確認。45度俯角の前後左右と平行投影を描画し、粒子なし時計0.9→0.2秒のシーク、既存射出/着弾の粒子PreviewのLoad/Seekを確認。Launcher dirty=false。

新しい画像・動画は生成せず、ユーザーがライブPreviewを確認した。Preview PNG6枚とmetaは指定により削除し、古い動画は旧体積版の記録として残した。画像生成やCI/自動レビューの待機を無断で評価手順へ追加しない。
