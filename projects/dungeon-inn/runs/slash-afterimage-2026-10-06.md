# 剣・短剣・大剣：フィードバック前の知識との差と採用結果

## 対象と承認

2026-10-06、ユーザーの「まぁ問題ないでしょう。これでいいです」を受け、SwordSlash / DaggerThrust / GreatswordSlashの基準版の見た目を採用する。最高品質を目指す制作段階の外観承認であり、ゲーム用削減・統合・実機性能の合格ではない。今回は分析と知識更新だけで、Unity・撮影・他エフェクト制作を追加実行していない。

対象は `1020001001_SwordSlash`、`1020003001_DaggerThrust`、`1020005001_GreatswordSlash`。GreatSwordSlashはユーザー呼称、保存アセット名はGreatswordSlash。旧SwordSlash_Gameの見た目承認を今回のSDF版へ置き換えたり、今回の承認を旧Game版へ継承したりしない。

知識の開始版はmain `127b196`。分析はその時点のノードを対象にする。実装側は `art/normal-attack-review`、HEAD `d6781bb3`を祖先とする未コミット作業。d6781bb3に今回のShader・素材が含まれるという意味ではない。保存ファイルは[SHA256スナップショット](slash-afterimage-2026-10-06.artifacts.json)で区別する。

## 差の分析

| 旧知識・制作判断 | 起きた差・指摘 | 採用した判断と今後の防止 |
| --- | --- | --- |
| Sword/Greatswordの主案が振りの位相で弧を展開し、実刃の履歴を必須にする | 判定後なのに振り始めを見せてしまう | 既に通過した空間の完成形を最初から置く。動作中の刃と判定後の残像を採用入口で分ける |
| Daggerの主案が針状刺突 | 細い刃で素早く切る深い三日月にならない | 武器名やThrustという保存名から意味を決めない。全体の鋭い奥行きと細い帯を独立に設計 |
| 象牙白と青灰、薄い後流を主案にする | 金属・火花の色面と存在感が不足 | 金属は淡黄〜橙。主面の濃い領域と端の透明グラデーションを作る |
| alpha減衰・線形UVワイプ・角度ワイプへ単純化 | 方向が消える、根元が先に欠ける、参照と内側曲線が違う | 外形を固定して内側曲線を動かす。厚みの縮小と戻り端の短縮を照合する |
| 指摘された要素だけを置換する | フェードイン、流れ、他の成立した要素まで失う | 形・色・濃さ・立上り・内部流れ・消失方向・終端・補助層の維持一覧で差分レビュー |
| ピークまで保持して残留後半に侵食する一般則 | フェードイン完了後に消失が始まる直列再生になる | 外部秒を共通原点にし、立上り開始から消失も並列に進める |
| 回転・座標の説明を実装へ直結 | 振り始めの座標を回転中心と誤解する | 武器の支点と弧の端点を分け、まず参照の四段階を言語化して曲線を照合 |
| 画素数や数式上の角度を合格根拠にする | 機械確認は通ってもユーザー意図の運動にならない | 参照の輪郭と通常速度の方向性を人間が確認。構造確認は補助証拠 |

既存知識の適用条件不足に加え、制作側が発火経路より武器名・一般的な展開案を優先し、変更のたびに既存要素を保持しなかったことが原因。知識を増やすだけでは防げないため、Brief・仕様・評価・採用対応表にも確認項目を追加する。旧技法・未使用武器・共有素材は削除しない。

[ユーザー提供の元画像](../references/slash-effect-user-2026-10-06.png)を変更せず保存した。上1/3は剣、下2/3は短剣、各四段階。黒い図形と透明背景のため明るい背景で確認する。コマの配置は空間移動の指示ではない。

外側の完成した三日月から、内側の抜きが外縁へ近づき、戻り側が短くなり、細い外縁が最後に残る。短剣は全体幅1に対して攻撃方向+Zの奥行5。短い刃を示す帯幅の細さと、深く食い込む内側が重要。切りと戻りを別の残像にすることは要求されていない。

## 採用構成と値

[Selection](slash-afterimage-2026-10-06.selection.yaml)は完成残像RecipeとUnity Adapter。静止Mesh+MeshRenderer、既存VfxShapeAlpha Shader、共有の円SDF一枚を内側の抜きだけに使用。VAT、頂点の時間アニメーション、実軌道Trailを必須にしない。色UVとSDF座標は分離。静的な描画支持面の拡張とBoundsは、頂点アニメーションとは区別する。

金属のsRGB指定は `#FFEAA5 → #FF9B45`。全体のalphaだけで消さず、十分な色面と縁の透明化を分ける。0秒は透明、フェードインはエフェクト全般の制作目安0.05〜0.1秒、今回0.075秒。これはフレーム数ではない。今回の承認対象ではHold=0、SDF輪郭開始=0で、フェードインと消失を並列に開始する。保留対象や既承認火球へ今回の変更を自動適用しない。

| 対象 | 主役と補助 | 主役の輪郭終了 | 各層の終了秒 |
| --- | --- | --- | --- |
| SwordSlash | BladeArc / SoftWake / FlowLines | 0.245 | 0.245 / 0.29 / 0.19 |
| DaggerThrust | ThrustNeedle / NearWake（保存名。見た目は深く細い三日月） | 0.14 | 0.14 / 0.19 |
| GreatswordSlash | LongBlade / DragWake / SplitFlow | 0.34 | 0.34 / 0.46 / 0.26 |

短剣の全体幅0.28m：奥行1.4m。大剣は剣の三日月を基準に幅広くし、残留を少し長くする。これらは今回の採用値で共通知識の普遍値ではない。ゲームの剣90度・大剣110度という判定契約は維持し、装飾三日月の曲率から判定を変更しない。接続は未実施。

SDFは512×512、RFloat/R32_SFloat、線形、Bilinear、Clamp、Mipなし。座標[-2,+2]の単位円 `length(p)-1`。同じプリミティブと変換で近似できる内側境界のため一枚が成立したのであり、任意の四輪郭を一枚で表現できる一般保証ではない。Materialのキー値はスナップショットの保存アセットと対応し、正式版は実装側の素材。

## 実行済み証拠と限界

Unity 6000.3.14f1 / URP 17.3.0 / Windows Editor / 専用Prefab Preview。以下はtask_0366〜0368の既存実行ログの転記で、新しい測定ではない。今回Graphics APIを再取得していない。

- task_0366：輪郭の代表四段階、最後の細い外縁の連続性、初期形内への残留、支持面とBoundsを確認。並列時刻変更前の結果であり、最新時刻の測定値と混同しない。
- task_0368：Riseを中立化した一時Preview Material、256pxの検査で0→0.0375秒の主役面積は剣6961→5541、短剣2599→1596、大剣8480→7479。立上り途中で輪郭が進む補助証拠。画素数は品質点やGPU時間ではない。
- 同task：通常素材で0秒透明、立上り中の表示、終端非表示、シーク再現差0。対象6件17素材の値/Shader確認は問題0、compile Error0/Warning0。六件検査のうち今回の記録・採用対象は三件に限定。
- 保存・再取込後に一部Material値が戻る例をSerializedObject保存とディスク照合で修正。保存済みアセットを検証前にgit addで保護。Sceneの未保存状態を保持しディスクを変更しなかった。

人間の見た目承認、機械チェック、内部構造レビュー、ゲーム統合、性能合格は別々に扱う。ゲームPlay・全件EditMode・対象実機・密集時CPU/GPU・DrawCall統合・他エンジンは未検証。PropertyBlockと共有素材があるだけでバッチング成立を主張しない。

## 次回の制作入口

1. 実装の発火経路から「動作中」か「完了後の残像」かを確定する。
2. 参照を全体比率、帯幅、外形、内側曲線、残す端、時刻に分けて言語化する。
3. 立上りと消失の関係、色面の濃さ、内部流れを維持一覧へ固定する。
4. 完成残像なら旧武器Recipeの実履歴・刺突・Contactを一括採用せず、新Selectionを使う。
5. 主役/補助/合成と通常速度を比較し、人間の再確認まで他への展開を止める。
