# 共通VFX：推奨構成の制作方針

共通Recipeの初稿候補を得るための制作方針。最高品質基準版は[Aの工程表](QUALITY_BASELINE_WORKFLOW.md)の完成像・時間設計・因数分解から作る。以下の形・配色・秒数を完成像や品質の上限へ固定しない。採用先のProfileで配色・カメラ・範囲・イベントを調整する。具体的なゲーム契約とIDの対応は `projects/` へ置く。

## 形で攻撃を読み分ける

| 分類 | 主役として採用する形 |
| --- | --- |
| 剣 | 細く鋭い入力角度θの弧と短い後流 |
| 斧 | 終端が厚い入力角度θの弧と遅れる刃重 |
| 大剣 | 長い外縁と幅広い入力角度θの刃面 |
| 鎌・旋風斬 | 一周する連続した弧。鎌は細く、旋風は発動の解放を強く |
| 実刺突の短剣・槍 | 攻撃軸の針と一点の圧縮。短剣の切りは深く細い三日月も比較 |
| 棒・拳・盾 | 接触の面、幅広い星、遅れる薄い圧力環 |
| 爪・牙 | 平行する短い切り線／内へ閉じる二点 |
| 矢・ボルト | ゲーム入力に従う実体と一本の短い尾 |
| 杖・ワンド | 丸い柔らかな核／小さく鋭い滴状核 |
| 火球 | 内部密度の炎塊、後方への侵食面、熱から煙への尾、一回の着弾膨張と冷却 |
| 火炎の息 | 実範囲に合う円錐殻と大きな炎舌の一回の解放 |

火球の改訂2は[立体火球Recipe](../knowledge/recipes/abilities/volumetric-fireball.md)と[実行Evidence](../evidence/organic-fire-volume-preview.md)を参照する。体積描画も候補であり、費用・画角・意味に合わせて採用する。

動作中の斬撃ではメッシュ展開を比較する。判定後の残像は完成した外形を置き、内側の消失を動かす。[完成残像Recipe](../knowledge/recipes/completed-slash-afterimage.md)を参照する。武器先端の実軌道に沿う部分だけ履歴帯を添える。粒子は火花・葉・破片・炎舌等の役割へ限定し、形状の曖昧な粒子雲で全ての攻撃を代用しない。

## 初稿の配色

以下は初稿候補のsRGB色指定で、金属攻撃の必須配色ではない。刃物・火花のテイストなら淡黄〜橙等の指定を採用先で優先し、色の濃い面と端の透明化を分ける。Materialの線形色・HDR発光値への変換はAdapterで行う。

| 用途 | 主色 | 面と芯 |
| --- | --- | --- |
| 物理攻撃 | 象牙白 `#EAE0C8`、補助の青灰 | 細い明るい外縁と暗い後流 |
| 無属性魔法 | 淡青 `#86CCF0` | 青の面と小さな青白の芯 |
| 火炎 | 橙 `#F68732`、赤 `#B7482B` | 小さな淡黄の熱核と橙の大きな舌 |
| HP回復 | ミント `#67DDA0` | 柔らかな葉・滴と短い白芯 |
| MP回復 | 淡青 `#53BDF5` | 細い結晶と静かな周回 |
| 攻撃強化 | 暖金 `#F3BD63` | 上向きの形と小さな付与ピーク |
| 攻撃低下 | 紫 `#9361BC`、暗紫 `#4B345D` | 欠けた下降形と低明度の面 |
| 土の衝撃 | 土色 `#9B8164` | 白い接触芯と薄い粉塵 |

色に加え、HPは葉、MPは結晶、強化は上向き、弱体は欠けた下向きで読む。敵味方の識別色は未提供であり、この属性配色から陣営を推測しない。識別を追加する場合はゲーム側の意味とProfileへ対応付ける。

## 明度と時間の仕上げ

主役の色面、細い発光芯、暗い外縁を別に持つ。小さなピークや大きな侵食は候補であり、時間の既定契約にしない。立上りと消失の開始・重なりを採用先で決め、判定後の残像では並列進行を比較する。全面の白い面にBloomだけを乗せる仕上げは採用しない。

予兆は中心へ集める、発動は外へ解放する、余韻は薄く裂いて消す。この運動方向を一貫させ、接触と無関係なタイミングに最も明るいピークを置かない。

Recipeの0.04秒ピーク、0.20秒減衰、粒子個数などは、初稿を制作するために選んだ値。採用先の詠唱・予備動作・速度・状態期間とは別の値であり、実測値ではない。

## 寸法と範囲

Wは対象Actorの身体幅、Hは身長、Lは武器の可視長、Rはゲームが渡す実範囲。物理寸法はメートルを基準とし、Actor/武器の寸法は実アセットのBoundsから得る。比率の基準を接続時に一つへ統一する。

主役の範囲境界は実際のR・角度で作る。装飾の拡大環と固定の境界を別にし、見た目のScaleでゲームの範囲を変更しない。斬撃の運動面は実モーション、地面境界は実判定の面へ置く。

## 準備・発動・飛翔・命中・状態の所有

- 準備は使用者、飛翔は実投射体、接触は実命中点、状態は実対象に置く。
- cast-start/cast-progress、attack-active、launch、impact/hit-confirmed、effect-applied/refresh/removeは必要な意味上の入力。この名前のイベントが既存コードにあるとは断定しない。
- 詠唱進捗と実発動に同期し、中断から成功演出を出さない。
- 状態applyは状態ハンドラが一回だけ所有する。詠唱Recipeと対象回復Recipeの参照は知識の共用であり、二つのEmitterを同時発生させる指示ではない。
- 自己強化Recipeは自分への強化。隣のActorへ広がるバフ波を出さない。
- 瞬間火炎コーンRecipeは一回の瞬間範囲。継続ブレスや刻みダメージを新設しない。

## 長時間状態の品質

長時間の活力は、良い付与の一回と小さな識別記号に分ける。大きな常時地面環・煙・火花を有効期間全体で維持しない。継続回復も回復刻みごとにフル演出を再生せず、実回復刻みでは記号と小光点だけを脈動させる。

Actor一体につきHP・MP・攻撃強化・攻撃低下をそれぞれ一組にまとめる。元の状態を複数保持し、代表する形だけ集約する。ゲームのスタック・回復量・期限は変更しない。解除・再付与・複合状態の各機能の終端は実データへ追従する。

## 修正できる構成として保存する

共通Recipeの主案は `composes: required` で記録し、採用先は採用先の対応表で採用先と個別調整を指定する。ゲーム固有ID・範囲・速度・期間を共通Recipeへ固定しない。これは「ファイアボールは世界中で必ずメッシュ」という一般則ではなく、具体的な推奨構成を選んだ結果である。比較用のcandidateは採用へ自動混入させない。

改訂時は主役の形・時間・素材・関係を変更し、revisionと索引を更新する。技法と素材を共有するが、実行時EffectId、Prefabの共用単位、Variantの境界はまだ確定しない。

## 参照した判断基準

行動・状態の伝達と、全体の一貫性・発生源の個性の両立は[Riot GamesのVFX教育資料](https://www.riotgames.com/en/artedu/visual-effects)を参照した。粒子の発生・運動と描画の分離は[Epic GamesのNiagara説明](https://dev.epicgames.com/documentation/en-us/unreal-engine/niagara-overview?application_version=4.27)を参照した。

上の具体的な構成・数値・配色は、このナレッジでの制作判断である。資料が採用先の効果を再現・検証したことを示さない。
