# 現在の到達点

## 知識基盤

**初期土台は構築済み。** 文書、ノード・選択記録のJSON Schema、索引・逆参照、検索・探索・必須依存解決、構造検証、テンプレート、テスト、CIを整備した。初期ノードはSemantic 2件、Composition 1件、Recipe 2件、Technique 2件、Evaluation 1件。

Windows / Python 3.13.2で以下を実行して確認した。

| 確認 | 結果 |
| --- | --- |
| 自動テスト26件 | 成功。Technique共有、同一役割の複数候補、新規ノードの索引・検索・逆参照反映を含む |
| 重複ID・未作成参照先・必須依存循環 | 不正入力を拒否。条件付きの必須循環も含む |
| 探索と採用・エンジン別Adapterの区別 | 候補・代替・補強・Adapter対応を自動採用しない |
| 自然言語条件 | 判断記録がなければ未判定。記録を渡しても自動評価とは表示しない |
| 文書だけでのvalidated付与 | エンジン実行記録のないRecipeを拒否 |
| 正本の構造検証と索引再生成結果の一致 | `validate --check-index` 成功 |
| 検索・選択例による依存解決 | 核の候補を検索でき、採用Recipe・Techniqueと必須Compositionだけを列挙 |

CIはUbuntu/Windowsで同じテストと索引一致を確認する。実行結果はGitHub Actionsで確認する。これらは構造・拡張性の確認であり、視覚・性能の検証ではない。

## 次の実証手順

1. 対象エンジン・版・Rendererと、操作・撮影・計測手段を決める。別プロジェクトの確認はユーザー許可後に行う。
2. ProfileとBriefにカメラ・美術・対象端末・同時表示・成功条件・性能予算を定める。
3. 一つの投射体Recipeで候補を選び、不足する素材・描画・着弾技法と対象Adapterを整備する。
4. 抽象仕様を実装し、発射・飛翔・着弾・停止・再利用を撮影・評価・計測する。
5. 観察から原因仮説を立て、少なくとも一度の修正と再評価を記録する。
6. 再利用可能な知見をEvidenceと知識更新案にし、レビュー・構造確認・必要な回帰確認を行う。

この循環を実行できて初めて、対象条件で制作ワークフローを実証したと報告する。
