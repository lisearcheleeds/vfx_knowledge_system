# B：完成基準版をゲーム用アセットにする工程表

改訂1 / 2026-10-06。Aの最高品質基準版が完成し、人間に承認された後の別工程。

入口は、[Aの工程表](QUALITY_BASELINE_WORKFLOW.md)で承認・固定された完成版。設計時に想定した層をそのまま削減対象へ流用せず、完成実物を改めて因数分解する。Aの原本は保持し、B用の独立した仕様・Selection・アセットを作る。

ここで初めてゲーム画角・表示サイズ・同時数・対象端末・CPU/GPU/メモリの予算を制作判断へ取り込む。未定の予算で性能合格を宣言しない。

| 工程 | ゴール | 成果物・次へ進む条件 |
| --- | --- | --- |
| B1 完成実物の再因数分解 | 形・時間・質感・光色・空間・各層の実際の貢献を把握 | 役割/構成/相互作用/費用の対応表。主役・補助・合成の比較 |
| B2 守る品質とゲーム条件 | 削減後にも必要な見た目と入力・寿命を明確化 | 維持項目と対象画角・サイズ・同時数・予算。未確定項目を明記 |
| B3 変換案の比較 | 情報を保つ削除・統合・近似・再配分を選ぶ | 層削除、描画方式、形/UV/時間等の採用・棄却理由 |
| B4 ゲーム用版の制作 | 変換案で品質を保持した独立アセットを作る | 新Selectionとアセット。基準版の必須層を黙って欠落させない |
| B5 外観の比較・再承認 | 失われた情報と残った情報を人間が判断 | 同条件の全体連続再生、層比較、外観の再承認。未達ならB1～B4 |
| B6 ゲーム接続・実測 | 実イベント・時計・位置・終了・再利用と対象実機で成立 | 統合確認と条件付き性能測定。費用不足は変換と外観比較へ戻る |
| B7 固定・知識還元 | 採用構成・制限・根拠を再現可能にする | 固定版、外観承認、統合結果、性能結果を別々に記録 |

削除の理由は見えない、貢献が小さい、合成を損なう等を実比較で示す。作り込んだ層も比較する。個別層の削除と、未使用武器・技法・共有素材を区別する。

変換後は開始・主動作・余韻・消失、方向・輪郭・視点・背景を全体で確認する。GPU/CPUは実際の条件付き測定で判断し、Renderer数・粒子数・透明面積・演算減少を性能改善倍率へ換算しない。

基準版の最高品質承認、ゲーム用版の外観承認、ゲーム統合、実機性能は別の判定。この文書の作成はBを実施した証拠ではない。
